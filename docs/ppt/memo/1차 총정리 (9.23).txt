2️⃣ 남연서 — KcELECTRA
설정: 구어체 사전학습 모델, weight_decay=1e-4, max_len=384
Epoch 7에서 0.6082 → threshold 최적화로 0.6268
오심이 유독 저조 (0.26 → 최적화 후 0.37)
오심은 "구역감", "속이 쓰리고" 등 표현이 매우 다양함
pos_weight 적용은 오히려 소폭 하락 (0.6050)

3️⃣ 최나현 — KoBERT
설정: 전체 fine-tuning, pos_weight, fp16
Freeze baseline 0.3799 → fine-tuning 0.5858 → threshold 최적화 0.6727
오심 라벨 샘플 중 관련 표현 등장 비율 5.5%
두통은 대원 질문에 신고자가 긍정했는데도 라벨이 빠진 사례 확인
LR scheduler는 효과가 뚜렷하지 않음 (0.5863, 세션 문제로 재검증 필요)

💡 팀 공통 발견: "오심"의 구조적 난제
3명 모두 독립적으로 오심이 가장 어렵다는 결론에 도달
KcELECTRA : 오심 F1 0.26 → 0.37 (thr 최적화)
KoBERT    : 오심 F1 0.44, 관련 표현 비율 5.5%
KLUE      : '기타' 계열이 타겟보다 많음,
            고열 라벨 누락 72.6%

→ 특정 모델의 한계가 아니라 데이터 라벨링 자체의 구조적 문제

💬 논의 필요
fine-tuning 범위가 성능 차이의 주요 원인일 가능성

thr=0.5 기준으로 전체 fine-tuning(KoBERT 0.59, KcELECTRA 0.61)이 3층만 fine-tuning(KLUE 0.52)보다 7~9%p 높아요. 그래서 "0.52~0.53이 라벨 구조상 상한선"이라는 KLUE 쪽 해석은 수정이 필요해 보여요

최종 성능 비교 기준 통일
KLUE 2차(0.5268)는 증상 없음 0%인 왜곡된 데이터에서 나온 수치라 비교에서 빼는 게 좋아요
KLUE 6차는 아직 threshold 최적화 전이라, 최적화 후 수치로 비교해야 공정해요

threshold 최적화 수치는 낙관적일 수 있음

같은 val set에서 threshold를 고르고 성능도 보고하고 있어요

데이터·split 조건 확인

KoBERT는 데이터 규모와 split 방식이 명시되지 않았어요
