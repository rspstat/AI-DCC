pw = pos_weight, LS = Label Smoothing, 화살표는 thr=0.5 → 클래스별 threshold 최적화

🔁 1차 → 2차: pos_weight 완화
1차는 recall만 높고 precision이 낮음 (오심 precision 0.17)
클래스별 최적 threshold가 0.75~0.85로 비정상적으로 높음 → pos_weight가 과해 확률 출력 자체가 편향됐다고 판단
weight = (neg/pos) ** 0.5로 완화
결과: thr=0.5 그대로도 0.5153 (1차의 최적화 후 수치와 동급), P/R도 0.51 vs 0.53으로 균형적
epoch당 23분 → 11.8분으로 단축

🔁 3~4차: 공식 Validation 평가
공식 Validation(wav·json 각 7,748개)으로 평가했더니 성능 급락
Label Smoothing은 역효과 (3차)
레이어를 3층으로 되돌려도 낮음 (4차) → 레이어 수 문제가 아님
🐛 중대 버그 발견
오디오 미션(1, 2) 코드를 재사용하면서 불필요한 wav 매칭 필터가 걸려 있었음
Training이 29,200개로 줄면서 증상 없음 비율이 0%로 왜곡 (원본은 53%)
필터를 제거해 62,362개 전체를 확보하고, 증상 없음 비율도 정상 반영됨을 확인
참고: json 62,362개 중 wav는 29,200개만 제공됨 (TS서울구급 기준). VS/VL은 1:1 완전 매칭

💡 3~4차 성능 급락의 진짜 원인
Training의 증상 없음 0% vs 공식 Validation의 증상 없음 53%
모델이 "증상 없음" 사례를 학습 중 한 번도 보지 못함 → precision 급락
공식 Validation은 학습에 사용 불가임을 재확인, 평가 전용으로 정리
