### 6. 텍스트 데이터와 NLP 기초

텍스트 데이터를 숫자 표현으로 변환하고 분류 모델을 활용하는 방법 이해

- 텍스트 데이터
    - 예시 : 문장만 보고 실제 재난 판단
    - 1. The forest is on fire. -> 재난 O
    - 2. This new song is fire. -> 재난 X
    - 문장은 단어 + 문맥도 고려 필요


---

데이터 분류 전체 파이프라인
- AI는 문장과 단어를 읽지 못한다. 문장과 단어를 숫자 배열로 바꿔야 한다.

![alt text](/study/img/55.png)

---

텍스트 데이터 특징

1. 문장마다 길이가 다름
2. 단어의 종류가 매우 많음
3. 같은 단어가 다른 의미로 사용됨
4. 단어의 순서 중요
5. 실제 텍스트에는 노이즈가 많음(URL, 해시태그 등)

---

텍스트 전처리
- 전처리를 많이한다고 무조건 좋은게 아님

1. 소문자 변환(Lowercasing) or 대문자 변환(Uppercasing)
    - 텍스트 데이터를 모두 소문자로 변환

```py
text = "Hello World"
processed_text = text.lower()

# 출력 결과
# "hello world"
```

2. 불용어 처리(Stopword Removal)
    - 불용어 : 일반적으로 사용되는 단어들
    - 텍스트 데이터의 크기를 줄이고, 처리 성능 향상

```py
from nltk.corpus import stopwords

stopwords = set(stopwords.words("english"))
tokens = ["I", "love", "to", "go", "the", "park"]
processed_tokens = [token for token in tokens if token.lower() not in stopwords]

# 출력 결과
# ['love', 'go', 'park']
```

3. 어간 추출(Stemming)
- 단어의 어미 제거, 단어의 형태 변화 고려 X, 단순히 어미를 자름(문제 발생 가능성 O)

```py
from nltk.stem import PorterStemmer

stemmer = PorterStemmer()
word = "running"
stemmed_word = stemmer.stem(word)

#
stemmer = PorterStemmer()
words = ['dogs', 'cats', 'horses']
stemmed_words = [stemmer.stem(word) for word in words]

# 출력 결과
# ['dog', 'cat', 'hors']
```

4. 표제어 추출(Lemmatization)
- 단어의 원형인 표제어를 찾는 과정, 단어의 형태와 문법적인 특성을 고려해 단어를 통합하는 방식

```py
from nltk.stem import WordNetLemmatizer

lemmatizer = WordNetLemmatizer()
word = "running"
lemmatized_word = lemmatizer.lemmatize(word)

#
lemmatizer = WordNetLemmatizer()
words = ['dogs', 'cats', 'horses']
lemmatized_words = [lemmatizer.lemmatize(word) for word in words]

# 출력 결과
# ['dog', 'cat', 'horse']
```

---

텍스트 정규화(Text Normalization)
1. 동의어 처리(Synonym Replacement)
    - 같은 의미의 단어가 다르게 표현된 경우(예: do not -> don't) 동일하게 처리
2. 오탈자 처리(Typo Correction)
    - 잘못 입력된 단어를 올바른 형태로 수정(예: teh -> the)
3. 줄임말 확장(Abbreviation Expansion)
    - 약어 전개(예: ASAP -> As Soon As Possible)
4. 숫자 처리(Number Normalization)
    - 숫자를 통일된 형태로(예: 100, 100.0, 1,00.0 -> 100)

토큰화(Tokenization)

- 문장을 모델이 처리할 단위로 나누기
- 예:
    - "machine learning is useful"
    - 토큰화 : ["machine", "learning", "is", "useful"]

![alt text](/study/img/56.png)

- 예2:
    - "산불이 확산되었다."
    - 토큰화 : ["산불이", "확산되었다"]
    - 형태소 or Subword 기준 : ["산불", "이", "확산", "되", "었다"]

- <PAD> : 문장 길이를 맞추기 위해 추가하는 토큰
- <LINK> : Vocabulary에 없는 Token

Padding, Attention Mask

- "길이가 다른 문장을 하나의 Batch로 만들기"
- AI는 여러 문장을 하나의 Batch로 묶어서 계산, 그러나 문장 길이가 다르면 하나의 직사각형 텐서 X, 짧은 문장에 Padding을 추가, 긴 문장은 일정 길이로 자름

```
문장 A: [2, 3, 4]
문장 B: [5, 8]
문장 C: [2, 7, 9, 4, 6]
```

- 동일한 사이즈의 텐서를 만들기 위해 '0'이라는 Padding 추가
- 그러나 모델은 2,3,4,5,8,0 등의 숫자 의미를 몰라 Check 필요

```
A: [2, 3, 4, 0, 0]
B: [5, 8, 0, 0, 0]
C: [2, 7, 9, 4, 6]
```

- Attention mask
- 1: 실제 값이 있는 Token
- 0: 의미없는 Padding Token
- A, B, C 각각 위치의 값이 무엇을 의미하는지 명시

```
A Mask: [1, 1, 1, 0, 0]
B Mask: [1, 1, 0, 0, 0]
C Mask: [1, 1, 1, 1, 1]
```

TF-IDF

- 특정 단어가 특정 문서 내에서 얼마나 중요한지를 나타내는 통계적 수치

![alt text](/study/img/57.png)

- TF(t, d) : 문서 D에서 단어 t가 등장한 정도
- DF(t) : 단어 t가 등장한 문서 수
- N : 전체 문서 수

---

예) D는 문서를 의미

```
D1: fire near city
D2: fire on stage
D3: earthquake near city
```

- fire -> 등장 문서 수 : 2, IDF 크기 작음
- near -> 등장 문서 수 : 2, IDF 크기 작음
- city -> 등장 문서 수 : 2, IDF 크기 작음
- earthquake -> 등장 문서 수 : 1, IDF 크기 큼

---

TF : 한 문서 안에서 해당 단어가 얼마나 등장했는가?
IDF : 그 단어가 전체 문서에서 얼마나 희귀한가?

임베딩(Embedding)

- 단어를 의미 공간의 좌표에 표현하는 방법

![alt text](/study/img/59.png)

- TF-IDF는 단어를 분류하고 중요성 판단
- 비슷한 단어끼리 연결하는건 한계 존재
- 예:
```
Token ID                            Token IDs: [Batch, Length]
25

↓                                   ↓

Embedding Layer                     Embedding

↓                                   ↓

[0.12, -0.81, 0.34, ... , 0.07]     [Batch, Length, Embedding Dimension]
```

RNN과 LSTM

1) RNN (Recurrent Neural Network)
- 특징 : 앞에서 읽은 정보를 Hidden State에 저장
    - 첫 번째 단어 ~ 마지막 단어 모두 순서대로 읽고 저장해 '기울기 소실' 문제가 발생하여 앞부분을 잘 기억하지 못하는 현상 발생 가능

![alt text](/study/img/60.png)

2) LSTM (Long short-Term Memory)
- 특징 : Gate를 이용해 필요한 정보를 기억하거나 제거를 조절(Forget, Input, Output Gate)

![alt text](/study/img/61.png)

---

Trasformer와 BERT

1) Transformer
- 특징 : 문장 전체의 관계를 동시에 봄

2) Encoder
- input으로 들어온 자연어 시퀀스를 숫자형 표현으로 변경

3) Decoder
- 숫자형 표현 -> 자연어 시퀀스

4) Attention
- query와 key-value 쌍을 output으로 나타냄
- query와 key를 이용해 value의 가중합을 구해 어떤 정보가 중요한지 나타냄

---

BERT
- unlabeled text에서 컨텍스트를 양방향으로 고려한 representation을 사전 학습(Pre-training)
- 전학습한 모델을 fine-tune 하여 다양한 자연어 태스크를 수행할 수 있도록 만든 모델
    - 사전학습을 통해 언어의 representation, 즉 언어의 정보를 풍성하게 이해하고 있는 거대한 모델은 약간의 학습과 일부 데이터만 있다면 다양한 downstream task를 잘 수행

모델 비교

![alt text](/study/img/63.png)

- TF-IDF는 단순하고 매우 빠르고, 어떤 단어가 예측에 영향을 줬는지 확인하기 쉬움. -> Baseline으로 유용
- LSTM과 BERT는 단어 순서와 문맥을 더 잘 처리할 수 있지만, 학습 시간이 길고 구현과 해석 복잡. 데이터의 크기, 필요한 성능, 계산 자원, 결과 해석의 필요성을 고려하여 모델 선택.

핵심

1. 모델은 원문을 직접 읽지 않고 숫자 표현을 입력 받는다.
2. TF-IDF의 Vocabulary와 IDF는 Train 데이터에서만 학습한다.
3. 복잡한 모델을 사용하기 전에 간단한 Baseline을 먼저 구축한다.
