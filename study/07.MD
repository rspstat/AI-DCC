## Study

### 7. 오디오 데이터 이해와 특징 추출

오디오 데이터
- 모델은 소리를 듣지 못한다. 숫자로 바꿔서 인식.
- Waveform 형태의 숫자로 인식

```
실제 소리 -> Waveform -> Mel-spectrogram 또는 MFCC -> 딥러닝 모델
```

---

오디오 처리 전체 파이프라인

- 오디오가 어떤 처리를 거쳐 모델 입력이 되는가?

```
1. 실제 소리
2. 마이크와 디지털 변환
3. Waveform [Channel, Sample] -> 소리를 숫자로
4. Sampling rate 통일         -> 같은 시간 길이를 같은 sample 수로 표현
5. Mono 또는 다중 Channel 처리  -> 모델 입력 channel 수를 일관 유지
6. 길이 통일 Padding / Crop / Sliding window -> 하나의 Batch로 구성
7. 특징 변환 Spectrogram / Mel-spectrogram / MFCC -> 특징 추출
8. 모델 입력 Tensor
```
- 3~6 -> 전처리
- 7 -> 특징 추출

---

소리 -> 숫자 변환

1. 공기 압력의 변화
2. 마이크가 전기 신호로 변환
3. 일정 시간 간격으로 측정
4. 진폭을 숫자로 저장
5. Digital Waveform

- 실제 소리는 공기 압력이 시간에 따라 변화하는 연속적인 물리 현상.
- 마이크는 이 압력 신호를 전기 신호로 바꾸고, 오디오 장치는 일정한 시간 간격으로 신호의 값 측정.
- 이 과정이 Sampling

---

- 측정된 값이 무한한 정밀도로 저장될 수 없으므로 일정한 단계의 숫자로 표현.
- 이를 Quantization
- Bit depth는 진폭을 얼마나 세밀하게 구분할 수 있는지를 나타냄

---

- Waveform 값은 실제 소리의 의미를 나타내는 값이 아니라, 특정 시점에서 측정된 진폭. 모델은 이러한 값이 시간에 따라 변화하는 패턴 학습.

- Sampling : 시간축을 일정 간격으로 측정
- Quantization : 측정된 진폭을 일정한 숫다 단계로 표현

---

Waveform (파형)

- Waveform은 특정 시간에서 소리 신호의 진폭이 얼마인지를 순서대로 저장한 1차원 시계열 데이터
- 가로축 : 시간, 세로축 : 진폭
- 특정 지점에서 다음 등장하는 그 값까지 period(주기)라고 함.
- Frequency(주파수) 개념으로 확장됨
- 주파수는 Hz 단위 사용, 1초에 100번 주기가 발생하면 100Hz.
- f = 1 / T

Sampling rate와 Duration
- Sampling rate는 오디오 파일의 전체 Sample 수가 아니라 1초당 측정 횟수
- 같은 1초 오디오라도 Sampling rate가 다르면 Sample 수가 달라짐
- Duration은 총 시간과 같음

![alt text](/study/img/65.png)

- Sampling rate가 높다고 성능이 좋아지는건 아님
- 분석하려는 주파수 범위와 사용할 모델, 계산 자원을 고려하여 결정

오디오 전처리
- 딥러닝에서는 여러 데이터를 하나의 Batch로 묶어 계산
- 각 오디오의 Sample 수가 다르면 하나의 일정한 크기의 Tensor로 구성하기 힘듦
- 이때, Padding, Crop, Sliding Window 등 전처리 기법을 통해 동일한 크기의 Tensor로 변환이 필요

예시
```
A : 0.7초
B : 1.0초
C : 2.4초
D : 8.0초

# 16 kHz 기준으로 Sample 수 확인
0.7초 -> 11,200 sample
1.0초 -> 16,000 sample
2.4초 -> 38,400 sample
8.0초 -> 128,000 sample

# 짧은 오디오 -> Padding
# 긴 오디오 -> Crop
# 매우 긴 오디오 -> Sliding Window
```

Frame, Window, Hop length
- 오디오는 시간이 흐르면서 주파수 특성이 계속 변함, 전체 오디오를 한 번에 분석하지 않고 매우 짧은 frame으로 나누어 각 frame의 주파수 계산
- Window가 짧으면 변화하는 모습을 세밀하게 관찰 가능, 하지만 한 frame에 포함되는 신호가 적어 주파수를 세밀하게 관찰 불가
- Window가 길면 주파수를 잘 구분할 수 있지만 시간 해상도가 낮아짐
    - 1. Frame은 분석할 시간 구간
    - 2. Windows는 Frame의 경계를 부드럽게 처리
    - 3. Hop은 다음 Frame으로 이동하는 간격

시간 영역과 주파수 영역
- 시간 영역에서는 신호가 언제 강해지고 약해지는지 볼 수 있음
- 주파수 성분 자세한 확인은 Waveform으로만 힘듦

Fourier trasform
- 복잡한 신호를 여러 개의 단순한 주파수 성분으로 분해
- 그 결과 어떤 주파수가 얼마나 강하게 포함되어 있는지 확인 가능
    - 그러나 시간 정보 사라질 수 있음
    - STFT로 해결

STFT (Short-Time Fourier Trasform)


- 긴 오디오를 짧은 Frame으로 나누고, 각 Frame에 Fourier Trasform 적용
- 시간과 주파수 동시 표현
- 가로축 : Time frame
- 세로축 : frequency
- 색 or 밝기 : Magnitude or Power

---

Spectrogram
- 시간에 따른 신호의 주파수 스펙트럼 변화를 나타낸 2차원 이미지
- 스펙트럼이 특정 순간의 주파수 성분과 그 진폭만을 보여주는 1차원적인 정보라면, Spectrogram은 여기에 시간축이 추가되어 각 시간대 별로 그 순간의 스펙트럼을 보여주는 2차원적인 정보 제공

---

Mel-Spectrogram

- 오디오 신호의 스펙트로그램을 멜 척도로 변환한 것
- 멜 척도 : 실제 주파수를 인간의 청각 인식에 가깝게 매핑한 비선형 척도
- 인간의 청력은 낮은 주파수에서는 미세한 차이를 잘 감지하지만, 높은 주파수에서는 둔감함
- 멜 척도는 이를 반영하여 낮은 주파수(약 20 ~ 500hz)에서 더 세밀한 해상도를 제공하고, 높은 주파수에서는 주파수 간격을 넓게 설정하여 상대적으로 낮은 해상도를 제공함

MFCC(Mel-Frequency Capstral Coefficients)
- 멜 스펙트럼(Mel Spectrum)을 기반으로 하는 오디오 처리 기법.
- 프레임에 대한 멜 스펙트로그램을 사용하여 DCT(Descrete Cosine Trasform)을 통해 더욱 압축한 형태로 변환.
- 중요한 특성 추출 가능
- MFCC를 통해 오디오 데이터의 feature를 뽑아 벡터화 가능
- MFCC는 음성 인식에서 유용하게 쓰임

---

- Mel : 사람의 주파수 지각 특성 반영
- Frequency : 주파수 정보 사용
- Cepstral : Log Spectrum을 다시 변환한 표현
- Coefficient : 변환 결과로 얻은 개수
